# Demo kit components

RML twins of the Claude Design kit (the prototype's `*.dc.html` component files), one `<Name>.rml` + `<Name>.rcss` per component. Method: `arc-rml-translate` (literal 1:1 element tree, inline style objects become classes with the same declarations, `renderVals()` `??` / `||` fallbacks become `<prop default>`).

## Conventions

- **Import by package path**, never by bare name: `<dc-import name="/ArcRmlUIDemo/UI/Rml/Demo/Components/Badge" .../>`. Nested imports inside the kit do the same.
- **Sheets.** A component never links a sheet. The expander injects the sibling `<Name>.rcss` of every imported component; the document links `/ArcRmlUIDemo/UI/Rml/Demo/tokens.rcss` first. `SearchField.rcss` is empty (it only wraps `TextField`).
- **Classes** are prefixed `dk-<component>`; modifier classes (`secondary`, `sm`, `selected`, ...) come from `data-class-*`; values that cannot be a class (percent widths, positions, grid columns) use `data-style-*`.
- **Props.** kebab-case attributes for camelCase props. Boolean props: pass `{{ true }}` / `{{ expr }}`; a static `"true"` / `"false"` string also works, anything else is truthy-by-conversion only for `1` / `true`. Numbers: bind them with `{{ }}` (static numeric strings are converted by RmlUi, but `+` on a static string concatenates). Array props (`tabs`, `options`, `items`, ...) take a whole-value `{{ path }}`; a missing array prop is `ArcEmpty`.
- **Icons.** `<i class="dk-x-icon"><svg src="/ArcRmlUIDemo/UI/Rml/icons/<name>.svg" width= height= stroke-width=/></i>` for a fixed icon, `data-attr-src="$icon"` for a prop, whose value is a full path with the extension (no `arcicon` transform). `svg { display: block }` per icon wrapper reproduces the painter's `svg.style.display = 'block'` (`icons.js:20`). `img:` / `asset:` icons are not used by the prototype and not ported.
- **Callbacks** (`onPress`, `onChange`, `onSelect`, ...) do not exist in RML:
  - Components with a **single click target** keep no handler. The screen puts `data-event-click="call('', 'Fn', args)"` on the import, calling its own view model function; the expander passes it to the component root (no kit component uses `data-action`). Applies to Button, IconButton, MenuItem, Card, ListRow, ItemSlot, FilterChip, TalentNode, QuestEntry, SaveSlotCard, ServerRow, PlayerCard, FriendRow, AchievementCard, RewardChip, SettingRow, Toggle (`change`), Checkbox (`change`).
  - Components with **several click targets or inputs** call **fixed function names** of the nearest `data-model` (the screen's view model), with the `field` prop (the caller's field id, `area` for TabBar) as the first argument; a screen implements only those its components use. TabBar `TabSelected(area, index)`, RadioGroup / Dropdown option / ContextMenu row / Breadcrumb crumb (not the last) / Pager arrow `Selected(field, index)` (Pager passes the new page), Stepper `Stepped(field, -1 | 1)`, SettingRow reset button `FieldReset(field)`, Modal button `Choose(index)`, AttributeRow `AttributeStep(index, -1 | 1)` and `AttributeInfo(index)`, KeybindField `KeyBound(field, ev.key)` and, on Escape, `KeybindCancel(field)`, Slider `SliderInput(field, ev.value)` (from the range input's `input`), FriendRow's open menu `Back()` on Back, Dropdown's open options `CloseDropdown(field)` on Back and on `blur` unless focus stays inside the owner the screen names with `data-focus-owner` on the import that holds every trigger of the list (`callIf(!ev.related_in_owner, ...)`; Settings puts it on the SettingRow import, every other screen on the Dropdown import; a press outside the owner closes the list, a press inside it leaves the close to the trigger's own click, which toggles it; the core keeps focus in the contained area while the pointer moves and clicks in it). There is no string-kind dispatcher.
  - DevBar calls the `ui` model's `SetTheme(theme)`, `SetInputScheme(scheme)`, `Jump(screen key)` and, for the session button, `ToggleMultiplayer()`.
  - HudDebug names its models: the Actions group is `data-model="hud"` (`OpenVendor()`, `OpenCrafting()`, `EndMatch()`, End match only while `bMultiplayer`), the Global group `data-model="ui"` (`SetTheme(theme)`, `SetInputScheme(scheme)`, highlighted from `Theme` / `Input`). HudDebugItems calls the row's `Fn` on its import's model: toggles `Fn(!On)`, buttons the option's `Fn()`, the slider `SliderInput(Fn, ev.value)` (generated on all four `BP_HudPort*VM`; it calls the `Fn` of that row, a no-op on the State, Bars and World models, whose debug rows have no slider).
  - A **disabled** component still receives the pass-through handler, because pass-through attributes land on the root regardless of state. Screens guard with `callIf(!disabled, '', 'Fn', ...)` or the VM ignores the action.
  - Numeric action values are sent as strings (`'' + i`); the VM converts.
- **Focus** (plugin `.agents/contracts/input.md` "Keyboard and gamepad navigation"; no view model owns focus). A component with one focus stop takes `focusable` (default off): the class `focusable` sets `tab-index: auto; nav: auto` on its focusable element, so the element is a stop and leaves its area by geometry. `disabled` does not remove the stop: a disabled item the mockup keeps reachable stays a stop (WAI-ARIA APG), and the caller guards its call. Exception: an `ItemSlot` that is locked, or disabled and empty, is never a stop. No component calls the view model on focus; the caller's `data-event-*` on the import gives the view model its context. The per-component `focused` look props are not ported: their declarations are the `:focus-visible` rules. `Modal` `focused` is a different prop (below). Inside a `SettingRow` the row is the stop, so `SettingRow` styles `:focus-within`.
  - Components with several click targets keep `field` (TabBar and AttributeRow: `area`, AttributeRow also `index`) as the context of their own calls and are a stop when it is set: SettingRow, AttributeRow, ContextMenu rows, Dropdown, Stepper, TabBar tabs (not when disabled), Breadcrumb crumbs (not the last), Pager arrows (`IconButton`s, `focusable` when `field` is set).
  - `nofocus` (Stepper, Dropdown, TabBar, Breadcrumb, Pager): the component needs `field` (TabBar `area`) for its calls but must not be a stop (inside a `SettingRow`). TabBar tabs with `nofocus` take the class `cycle` (`tab-index: auto; nav: auto`): the host's `data-hotkey-cycle` collects only `tab-index: auto` items, and a tab bar outside every focus area is never reached by the arrows from an area (plugin `.agents/contracts/input.md` "Spatial navigation, areas and leaving"), so the tabs are cycle items but no navigation stop.
  - `FriendRow`'s open menu holds the focus area `menu` (`data-focus-parent="list"`, `data-focus-contain`), on a child of the `data-if` element so the hidden placeholders of closed rows carry no area; the menu's rows are the `ContextMenu` stops. The menu area calls `Back()` and stops Back, so the view model closes the menu instead of the host returning focus to `list` with the menu still open. The screen puts `data-focus-enter="menu"` on the `FriendRow` import, so focus enters the menu its click opens.
  - Stepper `index` is the current step and Pager and LoadingTip `index` the current page; none of them is passed to the call (the call carries `field` only).
  - RadioGroup, ObjectiveRow, ScoreboardRow, Toast, Divider and the display-only components are no stops in the screens (the mockup never focuses them; RadioGroup / Toggle sit inside a `SettingRow`). Toggle and Checkbox still accept `focusable`.
  - `Slider` is a native `<input type="range">` (plugin `.agents/contracts/forms.md` "Range input"), so the mouse presses and drags it and Left / Right step it; it is the focus stop of its `SettingRow`, which the screen gives `nofocus`. Its look comes from `::-webkit-slider-runnable-track` / `::-webkit-slider-thumb` rules under `appearance: none` (`Slider.rcss`).
  - `Modal` `focused` (button index, default `-1`) passes `autofocus` to that `Button`: a cold open (the Dialog document) lands on it, and so does an entry into the in-document confirm's area.
  - `Dropdown`'s open options are the contained area `dropdown`; their container carries an empty `data-focus-enter`, so a click on an option starts no entry from the row's `data-focus-enter`.
  - `autofocus` (MenuItem, SaveSlotCard, ServerRow, SettingRow, ItemSlot, ListRow, Stepper, Slider, Button): sets the `autofocus` attribute on the focusable element (the root; Slider's `<input>`), so a reopened screen focuses the element the view model's selection names (return to the opener).
  - Click propagation: Dropdown (box and options) and the SettingRow reset button call `stopPropagation()` after their call, so a `SettingRow` click handler on the import does not run a second action for the same click.
  - `TalentNode` and `ItemSlot` take `nodeId` / `slotId` (set as the element `id`) and `navUp`, `navDown`, `navLeft`, `navRight` (bare element ids without `#`; the component writes `nav-up: #id`, `auto` when empty) for explicit neighbour tables.
- **Text fields.** `TextField` (and `SearchField` through it) and `KeybindField` contain a native `<input>` with `field` (the field id the screen's model knows). TextField: only `data-event-input` -> `TextInput(field, ev.value)`; the field behaves as Chrome's (plugin `.agents/contracts/forms.md` "Form controls"). KeybindField: `data-event-keydown` -> `KeybindCancel(field)` for `ev.key == 'Escape'`, else `KeyBound(field, ev.key)`. The value is shown with `data-attr-value` (one-way: `data-value` would write the read-only model on `change` and warn; plugin `.agents/contracts/forms.md` "Form controls"). The box restyles with `:focus-within`. `KeybindField` is a `readonly` input laid over its box with `opacity: 0`, so the box keeps the mockup tree and the input takes the focus and the keys. While `state` is `listening` its keydown stops propagation, so arrows do not navigate and Enter / Space do not click the row.
- **Input prompts.** `InputPrompt` takes `keyLabel` (and `padLabel`, `glyph`, `label`, `size`, `disabled`); screens pass `key-label="{{ ArcKeys.<IA name> }}"`, so a rebound key shows. A screen-wide action key is a `data-hotkey="<IA name>"` attribute (the prop `padHotkey` adds a second, pad-only action; no screen uses it) on the import together with `data-event-click` calling the screen's model, so the key runs exactly while the prompt is visible and clicking the prompt does the same. `PromptBar` has no props; its prompts are its children (`<slot/>`).
- **Slots.** Components whose mockup renders `{{ children }}` in one place use the unnamed `<slot/>` (Panel body, Card, ListRow actions, SettingRow control, EmptyState actions, FriendRow actions, StatRow, SectionHeader, Modal). Panel also has the named slots `actions` (header, after the titles) and `footer`: a direct child of the import with `slot="actions"` / `slot="footer"` goes there. The screen sets `has-actions="{{ true }}"` to show the header for actions alone and `has-footer="{{ true }}"` to show the footer wrapper (border-top, padding). Modal puts its button row in Panel's `footer`.

## Deviations from the mockup

1. `focusable`, `field` (`area` / `index` only on TabBar, AttributeRow and GameMenuHeader), `nofocus`, `nodeId`, `slotId`, `nav*` props: the mockup marks the focused item with its `focused` look prop from the controller's focus copy; here the caller states whether the element is a stop and what context its calls carry.
2. Native `<input>` in TextField / SearchField / KeybindField; the fake caret spans, the `ui-caret` keyframes and the `password` prop (never used by a screen) are dropped. KeybindField input overlay: see Conventions.
3. **Panel `hasActions` / `hasFooter`**: the mockup shows the header when it has a title, an icon or `actions` children, and the footer wrapper only when it has `footer` children. RML cannot test whether a slot received children, so the screen states it with these props; `footer` children without `has-footer` are not shown.
4. **Lists built by JS**: Stepper pips (up to 8), Pager dots (up to 8) are fixed cells hidden by `count`; `Modal` shows every button (the mockup slices to 3); `ScoreboardRow` header slices labels with an index test.
5. **JS the expression language lacks**: `InputPrompt` decides the round cap from the glyph being `A`, `B`, `X` or `Y` (mockup: `txt.length === 1`); `PlayerCard` takes `initials` from the VM (no `slice(0, 2).toUpperCase()`); `StatRow` / `AttributeRow` / `ItemTooltip` deltas come as signed text (no `typeof` / `toLocaleString`); `ItemTooltip` takes the flattened set fields and `SellItems` instead of building them; `AchievementCard` formats numbers with `arcnum`.
6. **Geometry computed in JS**: `TalentLink` takes `len` and `ang` (precomputed `hypot` / `atan2` degrees) instead of `x2`, `y2`.
7. **Demo data removed from markup**: `GameMenuHeader` defaults for `who`, `tabs`, `currency` are empty (the mockup carries a demo tab list and currency).
8. **Style composition**: `ItemSlot` and `TalentNode` build `box-shadow` from five custom-property layers (`--sh-*`, default `0 0 0 0 transparent`) instead of joining a JS array; `ItemSlot` hover keeps only the border change (the hover background equals the base background); `Button` / `IconButton` / `Card` / `MenuItem` etc. express the `--h-*` / `--p-tf` custom properties per modifier class (hover and active rules are the mockup's).
9. **Click target**: `Toggle` and `Checkbox` pass-through lands on the component root (the mockup's `onClick` is on the track / wrapper); the Toggle label therefore also toggles. `Button` loading + selected keeps the selected hover look.
10. Replacement characters (`U+FFFD`) in the source copy (`PlayerCard` separator, `GameMenuHeader` and `DevBar` defaults, `KeybindField` and `TextField` ellipsis) are written as `·` and `…`.
11. `data-attrif-selected` (`selected=""` on the root) is added to Button, IconButton, Card, MenuItem, ListRow, FilterChip (`active`), ItemSlot, TabBar tabs, TalentNode, QuestEntry, SaveSlotCard, ServerRow, PlayerCard, FriendRow (host reads it for tab cycles).
12. `demo`, `hint-*`, the look prop `focused` (replaced by `:focus-visible`; `Modal` `focused`, the autofocus button index, is kept), `noFocus` props dropped. Callback props dropped (above).
13. **Ornaments** (prototype 1795260599-c35e): level 1 corners stay `::before` / `::after` (`opacity: var(--ui-ornament-1)`) as the mockup's `style-before` / `style-after`; the level 2 elements are spans named by role instead of the converter's `-e<N>` classes: `-orn-frame`, `-orn-corner` and `-orn-gem` with `tl` / `tr` / `bl` / `br` (Panel, Card; ItemSlot frame and corners), `-rule`, `-rule-bar`, `-rule-gem`, `-rule-line` (Panel title, SectionHeader). Declarations shared by the four corners or gems sit in the base class, their offsets and borders in the corner class; the values are the mockup's.

14. **HUD frames** (from the converter output of the HudPort port, imports moved to this folder; TargetFrame uses the kit `Badge`): object props (`health`, `resource`, `cast`) are view model structs read by field; the health label is `arcnum` (mockup `toLocaleString('en-US')`), the target label `| round` of `Value * 100`; TargetFrame shows its `CastBar` on `cast.Active` (the mockup tests the object); `BossBar` enrage time is `arctime` (zero-padded minutes, seconds round up; the mockup floors); `CastBar` time is `($seconds * 1) | format(1)`; PartyFrames (4) and BuffRow (12) cap their loops with `display: none` past the mockup's `slice`.

15. **HUD world markers** (converter output of the HudPort port, imports moved to this folder; all scalar props, no row contract): `DamageNumber` text is `arcnum` of `value * 1` (mockup `toLocaleString('en-US')`, `Number(...)` has no expression mapping) with the sign and `!` in the expression; `InteractionPrompt` has no `input` prop: its kit `InputPrompt` follows `ArcKeys.scheme` (the real scheme), so the glyph and key cap need no per-component scheme.

16. **HUD action bars** (converter output of the HudPort port, imports moved to this folder, shared `ItemSlot` of this folder): the mockup computes `keys[i]`, `gl[i % 4]`, `kk[i]` and the LT / RT sets in `renderVals`, so the lists carry them: `KeyLabel` / `Glyph` per row, `ActionSlot` shows `$glyph` on the gamepad scheme, `keyLabel` otherwise; `ActionBar` writes the two gamepad set rows (LT slots 0-3, RT slots 4-7, `A B X Y` glyphs by index) as `data-for` over `slots` with a display test per set and `dim` / `big` from `pad-set` (the converter leaves `sets` as external data); `ActionSlot` cooldown label is `| ceil` from 10 seconds and `| format(1)` below (`Number(...).toFixed(1)` has no mapping); `QuickSlots` cooldown label is `| ceil` of `Seconds`; `WeaponBar` Q / E (`LB` / `RB`) neighbour keys are one expression over `active` and `weapons.size` and the empty-ammo test is `Reserve <= 0`; the ammo text shows `Clip / Reserve` for `Clip >= 0`, else `Charges charges` for `Charges >= 0`, else `∞` (the mockup tests for a missing field, the struct holds numbers, -1 means none); `WeaponWheel` reads `weapons[0..7]` by index with `$weapons.size > i` tests (eight fixed spokes).
17. **HUD feed and info** (converter output of the HudPort port, imports moved to this folder; `LootFeed` `lines`, `QuestTracker` `quests` and `ScreenEffects` `hits` are view model lists, see the row contracts): the loop caps are `data-style-display` on the loop items (`LootFeed` last 6, `QuestTracker` first 4); the quest count is the `quests` size (`N tracked`); `ScreenEffects` takes `show-hits` (the hit arcs' region toggle) and has no `input` prop, since its kit `InputPrompt` follows `ArcKeys.scheme`; the respawn countdown is `arcmax(0)` then `ceil`.

18. **HUD debug menu** (`HudDebug.dc.html` with the groups of `GameUI.dc.html` `hudDebugGroups`; converter output of the HudPort port, imports moved to this folder): the groups are a flat list per HudPort view model (`HudDebugItems` over its `Debug` rows; a heading is the `Title` of the row that starts a group), so the order is the models' (state, units, bars, world), not the mockup's. `HudDebug` writes two groups in RML above the lists: **Actions** (Vendor, Crafting, End match; the mockup's World "Actions that left the pad" Trade / Craft / End match, with the `data-hotkey`s `IA_ArcDemo_OpenVendor` / `OpenCrafting` / `EndMatch`, which fire only while the menu is open; End match is hidden, not disabled, outside multiplayer) and **Global** (Theme with the five themes, Input; bound to the `ui` model, as `DevBar`), whose Show anchors / Safe zone / Time scale rows are the first, untitled rows of the state list. The slider is the kit `Slider` (native range, `SliderInput`) instead of the mockup's `onChange`; hold buttons (Hold LT / RT, Weapon wheel, Hold to interact) are click toggles.
